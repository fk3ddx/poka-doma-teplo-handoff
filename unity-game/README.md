# Атака на запоминание — Unity M0

Нативный проект **Unity 6.3 LTS (6000.3.26f1), URP 17.3.0**, Windows x64.
Это первая техническая веха из `../CODEX-BRIEF.md`, раздел 12. Предыдущие Three.js / Electron версии остаются в своих каталогах.

## Статус

**Windows-билд собран и запущен. 17/17 автоматических тестов прошли.** Проверка самого `.exe` завершилась кодом 0, записала пять кадров и не зарегистрировала ошибок. Отчёт и ограничения — [TESTING.md](TESTING.md). Живое прохождение пользователем ещё предстоит.

M0 содержит тестовую геометрию по размерам квартиры, контроллер, выбор интерактивов с учётом препятствий, двери, подбираемые предметы, переключатели, сохранения, паузу, настройки и лёгкий VHS. Мебель представлена явно обозначенными объёмами для проверки проходимости. Это не художественная приёмка и не новый сюжетный пролог.

## Открыть и собрать

1. Активировать редактор в Unity Hub своим Unity ID.
2. В Hub добавить этот каталог как проект и выбрать редактор **6000.3.26f1**.
3. Дождаться восстановления пакетов. В редакторе выполнить **Ataka → M0 → Generate test apartment**.
4. Открыть `Assets/_Project/Scenes/Apartment_M0.unity`, нажать Play. Меню появляется перед управлением персонажем.
5. В **Window → General → Test Runner → EditMode** запустить тесты.
6. **Ataka → M0 → Build Windows** создаёт `Builds/M0/Ataka-M0.exe`.

Из PowerShell (путь к редактору передаётся явно):

```powershell
./tools/build.ps1 -Editor 'C:/path/to/6000.3.26f1/Editor/Unity.exe'
```

Скрипт последовательно генерирует сцену, выполняет EditMode- и PlayMode-тесты, проверяет XML-результаты и только затем собирает Windows. Логи — `Logs/`, результаты — `TestResults/`. Для командной строки Unity на Windows используйте `Unity.com`, если вызывающая оболочка не ждёт завершения GUI-приложения `Unity.exe`.

Редактор и проект на Windows размещайте по коротким путям. На рабочей машине репозиторий доступен через `subst U:`; скрипту можно передать `-ProjectPath 'U:/unity-game'`. Сопоставление диска не исправляет повреждённую установку самого редактора. План проверок — [TESTING.md](TESTING.md), происхождение ресурсов — [CREDITS.md](CREDITS.md).

## Управление M0

WASD / левый стик — ходьба; мышь / правый стик — обзор; Shift / нажатие левого стика — бег; Ctrl / B — присесть; E / A — взаимодействовать; Esc / Start — пауза. В меню паузы — сохранить, загрузить, настройки.

Спички доступны стоя со стороны передней грани холодильника. Из приседа корпус холодильника действительно перекрывает их: приоритет не разрешает брать вещи сквозь твёрдую геометрию. Тест это проверяет. Окончательная высота и размещение мелких предметов проверяются в M1 на художественных моделях.

Сохранения M0 отделены от будущей сюжетной игры: `checkpoint-m0.json` и резервная копия в `Application.persistentDataPath`. Настройки — `settings-m0.json` там же. Секреты и токены проекту не нужны.

## Что ещё не реализовано

- Художественное наполнение, PBR-ресурсы, лайтмапы, полноценный двор и лестница — M1.
- Бабушка, диалоги, новости, сюжет и единственный откат — M2.
- Монстр, прятки, смерть, другие версии квартиры и финалы — M3–M5 после приёмки M1.
- Посадка в кресло, предметы в руках, частичное открывание дверей мышью, переназначение управления, звук и полноценные настройки качества ещё не входят в этот каркас.
- EditMode-тесты не заменяют PlayMode, живое прохождение, измерение FPS и визуальную приёмку.

## Следующий шаг

Проверить M0 на своём управлении, исправить замечания по каркасу. Затем M1: разобрать реальные игровые кадры референсов и наполнить квартиру качественными моделями, материалами и бытовым звуком. Не переходить к монстру до одобрения художественной квартиры.
