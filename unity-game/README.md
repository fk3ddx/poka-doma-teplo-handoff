# Атака на запоминание — Unity M1

Нативный проект **Unity 6.3 LTS (6000.3.26f1), URP 17.3.0**, Windows x64. Художественная квартира для проверки перед сюжетной вехой. Общий сценарий — `../CODEX-BRIEF.md`.

## Что можно проверить

Обставленные зал, кухня, спальня, прихожая, ванная, балкон пятого этажа и два лестничных марша. Ковры, стенка с книгами и посудой, диван и кресло, торшер, CRT с вымышленной восьмибитной игрой, кофе, холодильник, плита и радиоточка. За окном — холодный двор с домами, голыми деревьями, снегом, скамейками и укрытыми машинами.

Можно ходить, открывать двери, подбирать спички и тетрадь, переключать свет, сохраняться и загружаться. Есть пространственный бытовой звук и отключаемый лёгкий VHS. Для общего блэкаута подготовлены отдельные лайтмапы. Это Development Build для художественной проверки, не законченный сюжетный пролог.

Настоящие игровые кадры и сравнение с официальными скриншотами Fears to Fathom: **[QA/compare.html](QA/compare.html)**. Состояние проверок — **[TESTING.md](TESTING.md)**. История исправлений — **[M1-WORKLOG.md](M1-WORKLOG.md)**, происхождение ресурсов — **[CREDITS.md](CREDITS.md)**.

## Запуск

Распаковать Windows-архив целиком в короткий путь, например `C:/Games/Ataka-M1`, открыть `Ataka-M1.exe`. Unity Hub и аккаунт для запуска готового билда не нужны.

WASD / левый стик — ходьба; мышь / правый стик — обзор; Shift — бег; Ctrl — присесть; E — действие; Esc — пауза, сохранение, загрузка и настройки. Спички лежат на холодильнике; брать стоя со стороны передней грани, не через корпус. Рекомендованы наушники.

## Сборка из исходников

1. Добавить `unity-game` в Unity Hub, выбрать редактор **6000.3.26f1** и активированную лицензию.
2. Открыть сохранённую `Assets/_Project/Scenes/Apartment_M1.unity`. Готовая сцена и ресурсы уже в репозитории; Blender для обычной сборки не нужен.
3. Для регенерации: **Ataka → M1 → Generate furnished apartment**, затем `Ataka.Editor.ApartmentLightBaker.Bake` через batchmode. Генерация заменяет авторскую сцену целиком; ручные правки предварительно сохранять отдельно.
4. **Ataka → M1 → Build Windows** создаёт `Builds/M1/Ataka-M1.exe`.

Полный воспроизводимый проход — генерация, две запечки света, EditMode, PlayMode, сборка:

```powershell
./tools/build-m1.ps1 -Editor 'C:/path/to/6000.3.26f1/Editor/Unity.exe' -ProjectPath 'C:/Games/Ataka/unity-game'
```

Пути редактора и проекта должны быть короткими. На рабочей машине используется `subst U:`. Для ожидания Unity из терминала нужен консольный `Unity.com`, скрипт выбирает его автоматически. Логи — `Logs/`, XML — `TestResults/`.

Генераторы мебели и ресурсов находятся в `tools/art/`. Blender-исходник — `tools/art/sources/ApartmentFurniture.blend`, Unity читает заранее экспортированный JSON. Текстуры уже включены; `download_resources.py` нужен только для повторного получения CC0-источников. Промпты сгенерированных текстур сохранены отдельно.

## Границы этой вехи

- Равенство графики с Norwood Hitchhike не подтверждено. Мелкие детали, материалы отдельных предметов и художественная цельность ещё нуждаются в оценке пользователя.
- Бабушки, диалогов, новостей, атаки памяти, монстра, смерти и концовок в этой Unity-вехе нет. Это M2–M5; художественная квартира должна получить оценку до перехода к монстру.
- Зеркала используют материал и отражения окружения, без полноценного зеркального изображения персонажа. Посадка в кресло и предметы в руках ещё не реализованы.
- При частичном выключении света меняются прямые источники и соответствующие светящиеся предметы; непрямое освещение хранится только для двух общих состояний — тёплого и полного блэкаута.
- Полного человеческого прохождения и проверки на разных ПК пока нет. Короткий автоматический замер FPS не доказывает отсутствие всех возможных задержек.

Сохранения M1 — отдельный `checkpoint-m1.json` с резервной копией в `Application.persistentDataPath`; M0 не перезаписывается. Пользовательские настройки пока общие с M0 (`settings-m0.json`). Сюжетный формат сохранений будет версионироваться отдельно.
