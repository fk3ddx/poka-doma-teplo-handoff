# 16 — Сетка проходимости до балкона (банка варенья, flow-f)

Codex в своём `StoryAutopilot` ждёт окончания движения двери. Я этот файл не трогаю, чтобы не было конфликта.

`APPROACH-FAILED` у банки (5.60; 1; −0.85) имел и вторую причину. Сетка `GranNav`, по которой автопилот проверяет пеший маршрут, начиналась с z = −0.1. Точки на балконе (плита z −1.3…−0.35) в неё не входили, поэтому маршрута к ним «не было» даже при открытой двери.

- **Z0 = −1.4:** сетка покрывает балкон.
- **Пол под клеткой обязателен.** Луч вниз должен попасть в коллайдер пола, иначе клетка закрыта. Без этого клетки за наружной стеной стали бы «свободным воздухом».
- **Балконная дверь добавлена в состояние сетки** (`NavState`). Раньше после её открытия сетка не перестраивалась и старая закрытая створка оставалась препятствием.
- Балконную дверь бабушка сама не открывает — это не комнатная дверь. Её открывает сюжет («Отодвинуть шпингалет»).

**Офлайн по `colliders-serialized/open.json`** (`tools/qa/gran-nav-offline`, обновлён тестовый Raycast):

| Проверка | Результат |
|---|---|
| (5.60; −0.60), дверь закрыта | маршрута нет, ближайшая (5.48; 0.28) |
| (5.60; −0.60), дверь открыта | маршрут есть |
| (5.90; −0.90), дверь открыта | маршрут есть |
| (4.60; −0.80), дверь открыта | клетка занята открытой створкой |
| (2.00; −1.00), (7.50; −0.80), (4.00; −1.39) — воздух за стеной и у парапета | закрыты |
| 9 прогулок бабушки | без изменений, все проходят |

Сетка стала примерно на 20 % больше: 154 × 167 клеток, плюс один луч вниз на клетку. Строится один раз на каждое состояние дверей.
