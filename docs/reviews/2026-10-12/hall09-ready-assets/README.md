# Hall09 — готовые предметы прихожей

## Изменение
По Claude review06/08: готовое трюмо VVMGames, телефон VEF strnroman, dirty rubber_boots Poly Haven, тапки headless_christ и деревянная вешалка Sousinho. Источники/CC-BY/CC0/изменения в CREDITS.md и SOURCE рядом с ассетами. Денег не потрачено.

Трюмо (6.90,0,3.80), ширина1.20, высота1.80, глубина по настоящим вершинам0.447 м (старый manifest давал консервативную глубину0.59). Масштаб равномерный. Фонарик горизонтально на высоте0.242 м: нижняя поверхность реального отделения на0.2345 м, поэтому прежняя предложенная y0.10 попадала под мебель. Телефон на столешнице y0.546. Вешалка90см, крючки около1.65м, лицевая сторона в комнату. Остальная расстановка по review08.

Первое E открывает правую авторскую дверцу, второе берёт фонарь, через0.8с створка закрывается. Используется прежний ScenarioDoor с защитой капсулы; открытие95°, проход при максимальном вылете1.13м. Предмет не выдаётся нажатием сквозь закрытую створку. Зеркало: существующий PlanarMirror,256px/8Hz, без рекурсивных отражений.

## Пойманные дефекты
- Первые готовые модели перекрывались оставшимися Kenney-тумбой/скамейкой/вешалкой. У FBX смещены pivots: выбор по Transform.position пропускал их. Теперь удаляются только эти старые предметы внутри прихожей по реальным renderer bounds. Кухонное радио сохранено.
- Извлечённые текстуры сапог имели WebP-байты с расширением.png, Unity оставляла сапоги белыми. Реально перекодированы в PNG, Ready-import теперь прекращает работу при невозможности загрузить Texture2D. Исправлен экспортный скрипт.
- Вешалка сначала была обращена тыльной стороной к игроку; развёрнута без изменения авторской геометрии.
- Непринятые кадры сохранены в rejected-overlap-and-import. Они не финальная картинка.

## Проверки и ограничения
hall-probe: реальный Windows Direct3D11, старт с меню, две E, отсутствие выталкивания, отступ/продолжение открытия, пауза таймера закрытия, взятие/скрытие фонаря, отражение256px, проход до кухни. Кухня временно разблокирована ТОЛЬКО в QA для проверки прохода; это не сюжетное изменение. Полный checks.txt/result.json рядом.

Кадры diagnostic-warm-* используют существующий WarmReturn в QA. Это честно отмеченная диагностика при свете, а не начальный свет петли. Обычный hall-cupboard-open-flashlight очень тёмный; луч до предмета свободен, но это не доказывает визуальную читаемость. Нужна оценка Claude, прежде чем менять утверждённый свет или расположение предмета.

Зеркало реально рисует комнату, но все три авторские секции пока используют одну плоскость отражения; качество боковых секций требует ревью. Модели Миши в отражении пока нет. На ракурсе телефона в первом круге появляется подсказка соседней закрытой двери — отдельный дефект приоритета взаимодействий, пока не исправлен.

Принятые свет/VHS, сцена спальни, поза Katcho не переделывались. Автоматический звук перехватывается и очищается перед выводом. Это не прослушивание и не приёмка голосов. Никакого утверждения о равенстве качества FtF или готовности всей игры.
