# Hall10 — исправления по review09, проверка в процессе

## Решения Claude
Источник: ../claude-review-09/README.md. Все три зеркальные секции временно мутные probe до готового Миши; фонарь ближе к краю, без нового света; физический луч выбирает действие, соседняя дверь не перехватывает E.

## Реализация
HallArt10 изменяет существующую Flat, не пересобирает спальню/свет. Сравнивает сериализованные Light-компоненты и материал VHS до/после, прекращается при изменениях. URP включён box projection для probe, версия движка не меняется.

Один HDR ReflectionProbe128 в прихожейА, refresh ViaScripting при смене существующих интенсивностей/цветов. IndividualFaces распределяет работу по кадрам. Probe исключает зеркальную геометрию(layer30), работает с тенями до18м. URP Lit зеркало: metallic1, smoothness.58, reflectance.8, без emission; грейдинг/VHS основной камеры. Нужны реальные кадры: описание настроек не доказывает качество.

Unity6.3 имеет UUM-129405: повторный RenderProbe может оставлять прежнюю картинку в atlas. После IsFinishedRendering вызывается texture.IncrementUpdateCount по официальному workaround; обновление не каждый кадр. Источник: https://issuetracker.unity.com/issues/4781/urp-realtime-reflection-probes-do-not-update-when-renderprobe-is-being-called-once-per-second . Свойства probe: https://docs.unity.com/en-us/engine/6000.3/manual/lighting-overview/reflections/class-reflection-probe . В нашей проверке отдельно подтвердить обновление при переходе в WarmReturn.

Готовый signal_flashlight имеет стекло внутри основного renderer. Исходный FBX прочитан Blender без модификации: Blender-slot1 — стекло160полигонов, slot2 — маленькая лампочка42полигона. Unity меняет порядок: signal_flashlight, signal_flashlight_light, signal_flashlight_glass. Поэтому установщик ищет слот по авторскому имени в исходном prefab, не копирует номер Blender. Это отдельная найденная ошибка, первая попытка по номеру1 была отброшена до показа.

Фонарь сдвинут к переднему краю и повёрнут нормалью основного стекла в коридор. Ограничение maxX7.095 не позволяет корпусу пересекать закрытую дверь; из-за авторской формы стекло может оказаться дальше3.5см. Фактические bounds в placement.txt, проверить кадром. Блик — материал/отражение, не emission или добавленная лампа.

ScenarioFocus: ближайшее физическое попадание луча, исключён собственный игрок; затем только при отсутствии попадания — ближайший угол допустимой цели. Для закрытой двери fallback запрещён. Телефон получил коллайдеры авторских mesh, его точка остаётся прежней. Сценарные события/секунды не менялись.

Это черновая запись реализации, НЕ подтверждение тестов/визуального принятия.

## Диагностика realtime probe
Первый реальный запуск не получил cubemap: в обоих профилях QualitySettings realtimeReflectionProbes=0. HallReflections теперь включает эту возможность только на время жизни сцены и восстанавливает прежнее значение при выходе. Это установленная причина первой ошибки; UUM-129405 — отдельная предупредительная правка atlas, не доказанная причина первого провала.

После исправления hall10-enabled-probe завершился exit0/passed=true/errors0, Direct3D11. Проверены завершение cubemap и повторное обновление после WarmReturn; соседняя закрытая дверь не перехватывает телефон. Визуально фонарь в обычной темноте всё ещё плохо виден. Проверка ScenarioSight.Clear означает отсутствие геометрического препятствия, а не распознаваемость предмета человеком. Надпись теста «visible» шире доказанного — не использовать её как арт-приёмку.

Зеркало на hall-mirror снято с включённым фонарём: яркое пятно само по себе не доказывает самосвечение. Для сравнения нужны одинаковые survey-ракурсы без фонаря. Новых источников света и emission не добавляли.
